# 演示录制与交付登记

对应 [Issue #7](https://github.com/Nuru-Banmian/AR-work/issues/7)。以下是待执行脚本，不是已录制或验收记录。手机、电脑各录一段 3–5 分钟真实画面，不使用模拟场景代替现场 AR。

## 准备

1. 按 README 启动 Go、React 和真机业务包，两端使用同一可达的局域网 Go 地址。使用单独的演示数据文件，例如后端工作目录下 `data/demo-issues.json`；若文件已存在则保留，不覆盖旧记录。重启仍使用同一路径。
2. 手机充电、解锁并允许相机；选择光线充足且有纹理的地面/墙面，默认深度关闭，跟踪正常后开始。现场清除私人信息，电脑避免显示个人通知和敏感配置。
3. 两端开始录制。手机用系统录屏，电脑用系统或已有录屏工具。先短录验证画面、方向、声音可读，再录正式段；手机分段限制时使用支持连续 3–5 分钟的工具。
4. 首次上报后进入手机详情读出完整 ID，并在电脑详情核对；两段都展示该 ID，口述或字幕说明时间对应。不要因编辑或重新标记再新建问题。

## 手机段：建议 4 分钟

| 时间 | 操作与预期画面 |
| --- | --- |
| 0:00–0:40 | 展示服务地址和测试连接，现场缓慢扫描纹理平面，出现定位正常 |
| 0:40–1:30 | 点击真实表面放置黄色草稿，调整选点，填写标题、描述、优先级并提交，展示成功 |
| 1:30–2:10 | 问题列表进入详情，展示 ID；配合电脑刷新核对，再由电脑切换处理状态，手机读取同一 ID 的状态 |
| 2:10–2:50 | 编辑内容并保存；电脑核对新内容且状态仍保留。可在内容尚未保存时由电脑改状态，展示草稿未清空 |
| 2:50–3:35 | 同一详情重新标记，扫描并选点；先取消展示原标记保留，再重新选点保存，保留同一 ID。不要重启相机后声称旧标记恢复 |
| 3:35–4:20 | 配合电脑停止并重启 Go，展示断线/恢复后列表或详情刷新，ID、已保存内容、状态仍在。可选展示当前会话标记随网页状态变色 |

录制中未完成的检查如实记为未验证。若跟踪丢失或发生退出，先保存真实问题和环境信息，不能通过拼接隐藏失败后声称连续稳定通过。

## 电脑段：建议 4 分钟

| 时间 | 操作与预期画面 |
| --- | --- |
| 0:00–0:40 | 展示 Go 地址、存储路径和启动命令；React 连接同一地址，说明这是局域网原型 |
| 0:40–1:30 | 等待手机真正上报；即使 SSE 自动出现也点击“连接并刷新”，打开详情并核对与手机相同的 ID、标题、优先级和坐标 |
| 1:30–2:10 | 通过网页切换待处理、处理中、已解决，手机确认读取；展示可自由重新打开 |
| 2:10–2:55 | 手机编辑内容、重新标记后，网页刷新，展示内容和坐标变化且 ID、createdAt、处理状态保持 |
| 2:55–3:40 | 记录当前字段，Ctrl+C 停止本次 Go；网页显示断线或刷新失败。原命令、原 ARWORK_DATA 重启，再刷新网页读取同一记录 |
| 3:40–4:20 | 手机核对重启后数据。可选 SSE：保存变化自动出现、重连自动补齐；最后说明会话坐标和稳定性限制 |

停止服务只操作本次启动的进程。无需删除数据文件、重装手机、清空应用数据或部署公网。网页“连接并刷新”即手动刷新入口，SSE 是否完成不阻塞必做流程。
