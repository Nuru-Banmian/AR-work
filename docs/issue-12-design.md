# Issue #12：现场固定图案自动校准

## 本次确认的规格调整

用户在本对话确认采用第一种方案并要求开始：不再要求打印预置定位卡；首次用手机拍摄现场已有、固定且平整的独特标牌/海报，登记实测宽高和位置。后续扫描同一图案，跟踪有效后自动校准位置与方向。保留 #12 的相对点位、版本、旧记录补定位和真机偏差验收要求。本文件记录优先于 Issue 旧版“交付打印卡”的本次变更依据；尚未修改 GitHub 规格正文。

## 用户流程

1. 设置 → 保存服务地址 → 现场参照：登记/选择。
2. 登记新参照：填名称、位置、实测图案宽高（厘米）。正对固定图案，使矩形图案四边贴合取景框；拍摄裁切框内图案，查看预览，必要时重拍。手机 ARCore 验证图案特征后才允许保存。拍整个房间不是该方案的输入。
3. 保存参照后选中该区域的参照；新增问题时扫描选定图案，跟踪有效后才允许选点和拍照，提交相对位置。
4. 历史详情 → 查看现场位置：先展示所需参照图片、位置、尺寸与版本；点击开始扫描后才开相机。只识别该版本，跟踪有效时显示恢复点位，丢失跟踪隐藏。
5. 参照移动/更换：选中原参照，登记下一版本；新版本成功保存会原子停用旧版本。旧记录仍可读，但需重新标记才能恢复。不能自动检测相同图案被移动，也不能区分两块相同图案的实体，禁止重复安装。

## 数据与边界

- 服务以文件快照原子保存记录、幂等创建回执和参照版本；参照版本不可原地覆盖。后端校验相对位置、注册版本、有效状态及尺寸，图片与元数据共同保存。图片的 SHA-256 由后端计算。
- JSON 的 `cardId` 为兼容字段名，现在标识任意登记的固定图案。相对坐标以图案中心和 AR 图像姿态为参照，单位米；不复用旧会话的绝对坐标。
- `GET/POST /api/references`：登记、下载和版本替换。每个服务最多 32 个版本；JPEG/PNG 每张最多 512 KiB，每边 256–2048 像素；JSON 请求最多 768 KiB。宽高各 0.05–5 米，图像宽高比须与实测比例相差不超过 1.5%。手机取景支持长宽比 1:4 至 4:1，最长边 1024 像素。
- 同版本同内容重试返回原结果；不同内容返回冲突。新版本停用旧版；不同身份的完全相同图片拒绝登记。不能保证识别近似重复图案，因此安装管理仍需人工确认。
- 参照图案和元数据按服务地址缓存，完整下载后可以离线识别；离线不能得知参照是否刚被远端停用。历史记录及快照的完整离线下载属于 #14，本次不宣称首次无网即可获取历史。
- 旧客户端仍可提交没有参照的记录，显示需现场补定位。已有关联参照的问题不能用无参照 PATCH 静默抹去定位。创建幂等回执不因参照后来停用而失效。
- 参照登记失败保留草稿，发送后的请求冻结；结果不确定时按原服务和原正文重试，本机保留待确认登记。明确拒绝后允许修正。取消或失败不能覆盖旧参照与已有问题。
- 首次设置无需第二部手机、纸卡或 Google 云锚点；自动校准需要相机重新看到登记图案，并不意味着任意环境自动定位。参照位置不动、纹理可辨、光照合适是使用条件。
- 问题快照当前沿用 #11 的内存预览；持久化与上传见 #13，重新标记时点位/快照共同替换见 #16。没有把这些后续任务视为已完成。

## 真机验收

先测量一个实际标牌的图案边界并记录名称/位置/宽高。完成登记后在至少三个可辨认的已知点采集记录，分别强制停止并重开应用，再扫描参照恢复。逐点记录参照到问题的距离、实际恢复偏差、光照、扫描耗时，以及遮挡/误扫/移出视野时的行为。测试后确定演示适用范围，不预先承诺厘米级、全园区或长期可靠性。
