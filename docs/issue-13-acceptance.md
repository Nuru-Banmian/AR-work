# Issue #13 现场快照与双端看图编辑

日期：2026-10-26（Asia/Shanghai）。规格：GitHub #13、父规格 #10；补充要求：手机和电脑点开记录都能看到保存的照片。

## 实现

- 手机选点后隐藏整个 Canvas 和检测平面网格，读取现场与 AR 标记；按比例预览、重拍，确认后进入表单。JPEG 质量 80；编码失败或超过 6 MiB 时停留预览并提示重拍。
- 新手机请求使用 `POST /api/reports`，必需 `snapshot`（图片原始字节的标准 base64），与标题、描述、优先级、位置一起提交。旧 `POST /api/issues` 与旧待确认请求保留兼容；新手机请求不能绕过必需照片检查。
- 图片与问题、幂等回执共享同一 JSON 文件的原子替换。只有落盘成功才发布问题与 SSE；失败不保留幂等键，不显示半条记录。问题返回 `snapshotUrl`；`GET /api/issues/{id}/snapshot` 读取当前图片，缺失返回明确 404。列表不携带图片字节。
- JPEG/PNG：最大 6 MiB，单边 16–8192 像素，最多 2400 万像素；检查格式、尺寸及完整像素解码。携图请求 JSON 最大 12 MiB；无图旧请求保持 64 KiB 限制。
- `PATCH /position` 可同时替换照片；已有照片的问题必须提供替换照片。位置、照片共同生效，失败保留原数据。`/content` 和 `/status` 不允许写点位或照片。无登录权限边界，本版不声称可防止伪装为手机的任意 HTTP 客户端。
- 发送前将完整请求、服务、端点、幂等键持久化到应用私有目录 `pending-report.json`；成功清除。失败和重启继续使用原请求。保留原 PlayerPrefs 待确认请求兼容。返回首页保留当前内存草稿照片；多条离线队列和未发送草稿跨重启保存属于后续任务。
- 手机详情显示按比例照片，支持打开/关闭大图、错误重试和旧无图提示；切换服务或页面取消旧下载并释放纹理。PC 列表缩略图、点击大图、图片失败重试、旧记录无图提示；可编辑标题、描述、优先级和状态，远端通知保留未保存草稿。手机沿用 SSE 后查询及草稿保留逻辑。
- 手机照片目前联网读取；不宣称已完成后续任务的离线图片缓存。
