# 永久删除与手机收敛 (#26)

基线 `0350f3c`（#25 技术交付）。`DELETE /api/issues/{id}` 正文 `{ "title": "当前完整标题" }`。标题不匹配返回 409；成功返回 `{ "data": { "id": "..." } }`，重复删除同 ID 返回同样成功。PC 确认框明确展示标题和不可恢复提示，要求输入当前标题；共用操作锁阻止保存、状态及重复删除竞争，失败保留记录和输入，成功才移除。其他 PC 通过 SSE 查询移除对象，其编辑草稿随该对象卸载，不能创建新问题。

接收端在既有互斥区内一次原子保存删除结果：从 issues/media/models 移除该问题，清除该问题 remarks 映射，原创建 requests 收缩为只有 issueId 的键映射，deleted 只记录被删 ID。无标题、描述、坐标、图片、模型或旧附件 URL 留在删除回执。全部后续事务均保留 deleted；旧 JSON 与旧创建回执仍兼容。删除落盘失败不更新内存，旧完整资料仍可读。删除前清理本数据集已识别的崩溃暂存；启动时以当前及已删除 ID 识别旧暂存，保护其他数据集和用户命名备份，不承诺物理介质安全擦除。

已删除 ID 的详情、照片、模型、内容/状态/位置修改返回 HTTP 410：`{ "error": { "code": "issue_deleted", "issueId": "...", "message": "..." } }`。旧创建键即使正文变化也返回该终止结果；旧/新重新标记请求均不恢复问题。照片改用 no-store。不存在且从未删除的 ID 保持 404。完整资料同锁提交，所以创建/替换/状态和删除竞争最终收敛到一个已删除 ID，不产生部分附件。

手机两个 version 1 队列增加 deleted 终态，保留 key/目的地/endpoint/远端 ID，清空冻结正文、照片、模型和回执；该终态不自动或手动重试，迟到 Complete/Fail 不能复活附件。410 必须含 issue_deleted 和非空 issueId，重新标记还核对 endpoint ID；其他错误仍保留原请求重试。完整查询额外返回 `deletedIds`（同一锁内取得的明确删除 ID 集合）。手机只依据这些明确删除 ID 清理，列表暂时缺失绝不推断删除，因此早发晚到的列表不会销毁刚确认的新创建；网络错误不推断删除。查询携带原 `X-ARWork-Receiver`，响应也必须以同名头返回匹配的身份，地址被另一接收端占用时不能清理原目的地；未知 ID 的待上传创建和其他接收端队列保留。

手机列表、已同步合并副本、打开的本地/远端详情、编辑草稿、待恢复重新标记和当前会话标记随删除清理，并明确提示删除。缺失记录不再从本地回执补回；独立 SurfaceScanStore 模型库和 OBJ 预览副本保留。断线恢复及应用重启通过完整查询和持久终态继续收敛。
