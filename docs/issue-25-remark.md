# 重新标记完整现场资料 (#25)

基线 `7cf7fef`。`PATCH /api/issues/{id}/position` 新请求沿用模型 DTO，正文为 `reportVersion: 2`、`position`、`snapshot`、`model`，必须带非空 `Idempotency-Key`。32 MiB 完整正文、照片及模型限制与 #24 一致。已有模型的问题拒绝旧客户端只替换位置/照片，避免混合版本；旧无模型记录仍支持既有位置/照片请求，新手机重新标记统一提交完整模型。

接收端在同一互斥区读取最新问题，仅替换现场资料及更新时间，不覆盖编号、创建时间、文字、优先级和状态。位置、照片、模型（包括局部标记）及去重回执通过一个 fsync + 文件替换提交，成功后才更新内存、通知 SSE。失败保留旧完整资料和可重试状态。模型/照片按问题 ID 覆盖，没有附件历史版本；临时文件退出时清理，不复制旧附件到回执。

持久快照新增可选 `remarks`，每个回执只含 `fingerprint` 和 `issueId`，同键异正文或异问题返回 409。同键重放返回当前问题，绝不重新应用旧替换。问题新增 `sceneRevision`（场景内容指纹）；响应额外包含 `replacementCurrent`，表明该回执对应场景是否仍为当前版本。较新替换后重放旧请求返回 false。完整重新标记后的旧创建回放也返回当前完整问题，避免旧位置配新附件；旧无模型创建回执保持兼容。

手机将完整请求先存入独立 `remark-queue-v1`，复用 ReportQueue/ReportQueueSender 的原子落盘、目的地身份握手、冻结正文与幂等键，使用 PATCH 发送。失败后锁定该完整请求，不重新生成正文；返回后或应用重启后，再进入同一问题的“重新标记”可重试原资料。取消采集不发送请求；已发送结果未知时返回只停止本次重试，保留请求并提示刷新核对，不能撤销已经成功的远端事务。

成功回执确认当前场景且仍有对应的当前会话 anchor，才提升新标记；进程重建或被更新替换覆盖的回执不能恢复旧 AR 世界坐标。没有可提升 anchor 时清理该问题的旧会话标记，读取最新服务器资料。完整回执后清理已同步创建副本及此次替换队列；列表查询中的 sceneRevision 也会清理迟到的旧创建本地副本。其他待上传问题和独立 SurfaceScanStore 模型库保持独立。清理失败保留回执供再次核对，不宣称完成。

PC 复用现有 SSE 重新查询、按 updatedAt 刷新图片/大图与重建三维查看器，无需新增页面状态；编辑草稿按问题 ID 保留。
