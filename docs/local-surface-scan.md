# 手机局部表面扫描

规格：[Issue #20](https://github.com/Nuru-Banmian/AR-work/issues/20)。当前仅在手机本地处理静止设备局部或单件物品，不使用电脑或云端重建。2026-10-27 真机测试中，用户确认两轮贴合和连续性可接受；这只覆盖当次场景，不是尺寸精度证明。

## 当前交互

1. 新增问题进入相机页。空闲只显示相机和正方形扫描框，不启动旧地面/墙面检测或深度采集。旧平面覆盖、平面/直接 Depth hit-test 备用标记路径及“深度辅助”开关已移除。
2. 保持至少 **0.5 米**，范围上限 3 米，没有近距档。底部空间范围 0.5 / 0.3 / 1 米指目标体积边长，与最低采集距离不同。
3. 开始扫描，点击正方形框内目标中心。使用与融合相同的 CPU 深度图、内参和方向转换读取 3×3 邻域中位数。缺失、距离不足、超出范围或前后景断层时拒绝，并给出具体原因。真机日志确认 0.494m 被拒绝、0.511m 接受，这些是深度估计读数，不是外部测距结果。
4. 缓慢横移并观察物品不同方向。只采集当前框内的新样本。已有模型随视角投影到框外并不表示新增框外数据；框内且体积内的背景仍可能进入模型，不包含语义分割。
5. **暂停后立即隐藏现场模型显示**，保留碰撞网格供点选。直接看实物并点击位置，可放置宽约 **2 厘米**、高 **2.5 厘米**的三角锥标记；尖端位于选点，锥体沿表面外法线伸出。没有扫描表面时不退回到地面或墙面选点。
6. 可补扫、旋转查看或保存模型。清除立即停止扫描、隐藏并释放旧表面、禁用碰撞，忽略旧后台任务结果，可以重新选择目标；独立问题记录、标记和保存模型保留。
7. 扫描、列表和预览期间禁止现场快照。暂停后快照只保留实物相机与标记，不显示扫描网格。保存问题继续沿用本地持久队列。
8. 暂停并等待后台任务结束后保存模型。首页“扫描模型”可离线重新打开，历史模型只用于独立预览，不恢复旧 AR 会话位置。

## 实现边界

- AR Foundation / ARCore 5.2.2 提供跟踪和深度。smoothed depth 为主输入，raw depth/confidence 作为可信支持和冲突筛选。当前设备深度为 160×90，CPU 内参对应 640×480；中心裁剪与等比缩放用于内参及 RGB，避免分别拉伸横纵坐标。补偿屏幕方向，采样时读取相机位姿。
- 手机端 96³ 有界 TSDF，截断 4 体素，至少 3 次观测、权重至少 0.6 才提面。marching tetrahedra 保留未知区域缺口，提取后清理小连通碎片。
- 至少 4 帧后，使用已观测 TSDF 梯度做受限点到面平移配准；只用高置信点，至少 32 对支持，每步最多 1cm、累计最多 3cm，欠约束方向以跟踪位姿为先验。不是完整六自由度 ICP、回环或全局位姿优化。
- 单个后台任务处理融合和提面，不访问 Unity 场景对象。约 2.5Hz 采集、约 1Hz 提面，静止降频。清除以体积身份隔离旧任务，切页取消延迟预览；过期任务失败不会中断新扫描。
- RGB 为顶点颜色，不是照片级纹理。90,000 顶点 / 160,000 三角形上限；到达上限暂停并明确提示部分表面，不称为完整模型。
- 文件位于应用私有目录 `surface-scans-v1`，版本化 `.arscan` 临时写入后重命名，带范围和损坏检查，同时生成米制右手坐标、顶点 RGB 的 OBJ。尚无 Android SAF/分享导出交互。
- 无跨会话定位、自动背面补全或透明/反光材质质量保证。细小按钮与缝隙可能被平滑；没有将合成算法误差称为手机精度。

## 相机恢复诊断

旧包在真实扫描/保存后重入仍能停住，空场景重入通过不足以证明修复。`after-save-camera-broken.log` 显示可用性已为 Ready，但阻塞在 `session.enabled=true` 内部，没有执行后续消费者启用。取消一帧间隔仍不足；最终改为在同一帧先准备相机消费者，再恢复原生 ARSession。最新包上述 6 轮重入通过，尚未新增并提交测试问题重复三次。

ARCoreLoader 5.2.2 的 Start/Stop 为无操作返回 true，所以不能把 manager.StartSubsystems 的对称调用单独视为根因修复。最终证据来自实际新帧、非黑视窗与组件顺序日志。

后续如特定场景仍错位或无网格，保留原始诊断与失败结果，不以增加融合帧数或平滑颜色代替实物验收。长时间发热、内存增长及更多材质/物体仍需单独覆盖。
