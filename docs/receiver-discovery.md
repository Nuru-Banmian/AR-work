# 接收端启动、身份与发现（#23）

## 使用

在仓库根目录执行 `./start.ps1`。API 首选 TCP 18088，网页首选 TCP 5176，各尝试起始端口至起始端口 + 9（不超过 65535）。API 用实际 `Listen` 保持监听成功的 socket；网页以 Vite `strictPort` 逐个实际启动，绑定失败时仅端口占用会继续尝试。启动失败明确报错，不把占用端口的服务当成本次实例。每次启动使用独立 `.local/start/<run-id>` 输出目录；退出脚本会停止本次子进程。

网页通过同源 `/api` 与 `/health` 代理连接本次实际 API，直接打开即可使用；不沿用旧 localStorage 地址覆盖启动配置。手动单独执行 `npm run dev` 时默认代理 `127.0.0.1:18088`，可用进程环境 `ARWORK_API_URL` 指定目标；正式静态部署不在此启动流程中。

手机设置中点击“扫描 / 重扫局域网接收端”，点击候选切换电脑，再点击“选择此电脑”。显示电脑名称与候选序号，成功后显示服务地址；没有接收端时给出同一 Wi-Fi、访客网络隔离和防火墙诊断。没有二维码。选过电脑后可离线采集，新草稿与请求均记住该身份；其他电脑的待上传资料保留原目的地。设置的手输地址只用于诊断，也必须握手后才保存。

## 协议和持久化

- UDP IPv4 18087 接收 `ARWORK-DISCOVER-1`，向来源单播 JSON `{id,name,protocol:1,port}`。手机向全局与活跃网卡子网广播，监听约 3 秒，最多接收 16 个候选，随后并行 HTTP 核对；主机地址来自数据包来源，不相信包内任意 URL。后台约每 20 秒重扫，只有已记忆的同一身份可以自动换址；采集和重新标记期间不自动切换。
- `GET /api/receiver` 返回 `{data:{id,name,protocol:1,port}}`。身份是数据目录中 `receiver.json` 的随机 128 位 ID，重启和名称/地址变化保持不变；`ARWORK_NAME` 可覆盖电脑名。不能删除/重建该文件来“修复”连接；损坏时启动失败并保留数据。身份只识别目的地，不构成认证。
- 目前一台电脑只运行一个 UDP 18087 接收端；发现端口绑定失败则整个新接收端明确退出，不启动无发现能力的半实例。多设备指不同电脑；复制同一 identity 文件到另一电脑会造成身份冲突，不受支持。
- 手机确认 HTTP 身份后持久保存队列目录的 `routes/receivers.json`，队列条目保留原始 `server`、正文、幂等键，增加可选 `receiverId`。同身份重发现仅更新路由；读取列表与上传按身份隔离。新提交在网络前保存身份；已有 version 1 条目继续读取，只有原地址握手成功才绑定身份。不能验证的旧条目失败保留，不猜测目标。
- 每次 POST 前再次握手，携带 `X-ARWork-Receiver`。接收端在读取正文前拒绝不匹配身份（409 `receiver_mismatch`）。旧客户端不带该头仍兼容。上传客户端关闭 HTTP 自动重定向，避免正文被转发给不同服务。正文和幂等键不因失败或换址重建。
- 防火墙需允许 UDP 18087 和实际 API TCP 端口；网页只监听本机。跨网发现、认证、模型上传和新管理布局由后续任务负责。
