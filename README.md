## 启动 Go

安装 Go 后，在新 PowerShell 窗口执行：

```powershell
cd backend
$env:ARWORK_ADDR = ':8080'
$env:ARWORK_DATA = 'data/issues.json'
$env:ARWORK_ORIGINS = 'http://localhost:5173,http://127.0.0.1:5173'
go run .
```

`ARWORK_DATA` 相对于服务工作目录，也可使用绝对路径；重启必须指向同一文件。只运行一个服务进程读写一份文件，不手动同时修改文件。存储采用临时文件、同步、替换后再更新内存；问题与幂等键结果映射保存在同一个快照，写入失败返回错误。兼容 #2 的旧数组文件，首次成功修改后保存为包含 issues / requests 的快照；降级到旧服务前需恢复备份。损坏数据文件会阻止启动，不会自动清空。

手机与电脑在同一局域网，使用 `ipconfig` 找到手机能访问的电脑网卡 IPv4 地址。启动示例使用 `http://192.168.1.8:8080`；#4 隔离验收使用 `http://192.168.1.8:18085`，详见验收记录。其他电脑应替换为自己的地址。手机不能使用 `localhost` 访问电脑。Windows 防火墙需允许该 Go 进程在所用网络接收入站 TCP 8080。不要关闭防火墙；端口占用时改用其他空闲端口，并同步修改两端地址。此次电脑的 IPv4 localhost:8080 被其他程序占用，验收直接访问局域网地址。

## 启动 React

```powershell
cd web
npm ci
npm run dev -- --host 127.0.0.1
```

打开 `http://127.0.0.1:5173`，填入同一 Go 地址，点击“连接并刷新”。网页保存该地址，提供加载、空列表、错误、重试以及 ID、标题、描述、优先级、状态、坐标和时间。若改用其他网页源或端口，将其完整 origin 加入 `ARWORK_ORIGINS` 后重启 Go。SSE 收到保存通知后自动查询；断线显示提示并重连，重连后全量查询，数据查询失败每 2 秒重试，仍保留手动刷新。

## 构建与运行 Unity

保留 `mobile/ar-probe` 工程和独立探测包入口。业务包复用同一 AR 跟踪代码，通过不同构建入口启用问题表单：

```powershell
cd mobile/ar-probe
.\build.ps1 -UnityEditor '<Unity安装目录>\Editor\Unity.exe' -Inspection
```

生成 `Builds/AR-Inspection.apk`（调试签名，包名 `com.arwork.inspection`）；不带 `-Inspection` 则生成独立 `AR-Device-Probe.apk`。构建入口生成对应场景及材质。业务包开启 Android 局域网明文 HTTP，供可信局域网调试。Unity 2022.3 的 Android Build Support、SDK、NDK、OpenJDK 必须安装；构建目标 ARM64 / IL2CPP / OpenGLES3，最低 API 26、目标 API 35。

1. 安装业务包，允许相机权限；扫描光线充足且有纹理的桌面或墙面，等待 定位正常。为降低运行负载，业务包默认 30 FPS、“深度辅助：关”，关闭深度子系统；点击底部开关可启用 “深度辅助：开”，深度辅助开启后优先使用深度命中。深度优先选点，无可用深度命中时回退水平/竖直平面。深度候选限定 0.5–5 米，纯白墙仍可能不准确。低负载设置不保证消除闪退，历史退出记录曾有系统低内存回收。详见 [AR 检测方案](docs/ar-detection-options.md)。
2. 在 服务地址 输入同一 Go 地址，点击 “测试连接”；成功、失败均有提示。地址经校验后保存到手机，重启应用后保留。
3. 点击现场表面放置方块，可继续点选调整位置。深度命中不要求绿色平面已生成；平面模式需点绿色区域。界面按钮、输入框和面板不会放置方块。没有有效命中时保留旧方块，不使用固定距离模拟落点。
4. 点击 “填写问题” 锁定位置，输入必填标题、可选描述，用 “优先级” 按钮切换 low / medium / high。“调整位置” 保留内容并允许重新选点。
5. 点击 “提交问题”；保存期间禁用编辑和重复提交。首次提交固定服务器、请求键和内容；失败后保留草稿并锁定编辑，再点提交用原请求重试。未确认的请求保存在设备上，应用重启后可继续重放，但不恢复旧会话方块。成功显示标题、优先级和待处理状态；编号可在问题详情查看，方块保留在当前会话。点击 “继续上报” 才生成下一次上报的新请求键。
6. 网页点击刷新，核对同一 ID；使用“处理状态”自由切换待处理、处理中、已解决，保存失败仍显示原状态。Go 重启后再次刷新，记录及状态仍存在。
7. 手机点击 “问题列表” 获取全部问题，点击一行重新查询详情；两页的 “刷新” 均查询后端。详情显示编号、当前状态和时间；历史坐标仅在管理网页查看。重启应用后仍可用保存的地址查询，不按历史坐标恢复 AR 标记。
8. 详情中编辑标题、描述和优先级，点击 “保存内容”。保存期间禁用重复操作，成功显示最新状态；网页刷新同一 ID 可见修改。手机仅提交内容字段，不覆盖网页修改的处理状态或位置；相同内容字段采用最后一次成功保存为准。
9. 校验、连接、404 或 500 失败提示原因并保留草稿，可修正或重试；详情刷新更新状态并保留改动过的内容。“返回列表” 和 “返回现场” 保留当前应用内草稿，再进入同一服务器和 ID 可继续编辑；未修改内容时刷新加载最新内容。历史内容草稿不跨应用进程重启保存，退出前应成功保存。新建待确认请求仍按原规则跨重启保留。
10. 历史详情点击 “重新标记”，重新扫描并点选地面或墙面。“保存位置” 只保存新位置；“取消” 丢弃替代草稿。保存中锁定重复操作，确认成功后才移除同一服务器、同一 ID 的当前会话旧标记并保留新标记。新建问题尚未提交的标记暂存，返回后可继续编辑；历史内容草稿也保留。
11. 保存明确返回 400/404/500 时原记录不变，替代标记仍为草稿；可重选、重试或取消。超时或回执损坏时结果可能已经落盘，界面明确提示取消后 “刷新” 核对；网络断线不能保证后端未保存。取消不发送位置请求。重启后需重新选点，历史坐标不会渲染到新 AR 会话。网页点击刷新显示最新坐标。
12. “同步” 显示手机 SSE 连接状态。上报、内容、位置和状态保存后，两端重新查询最新数据；手机列表、详情和当前会话标记自动更新。标题、描述、优先级草稿保留，状态与坐标独立刷新；推送不会移动替代草稿。手机回到前台会重连并查询。当前会话已保存标记：open 橙、in_progress 蓝、resolved 绿；待提交草稿黄，屏幕提供图例。仅给当前会话已有标记变色，不按历史坐标新建标记；“问题列表” 中的 “刷新” 保留作为兜底。

业务界面使用中文，内置中文字体；仅显示操作所需的定位状态、同步状态和颜色图例，移除平面计数、命中诊断、清除标记和退出应用按钮。位置是当前 AR 会话的米制坐标，不是园区绝对位置；重启应用不会按历史坐标恢复标记。未提交的草稿只在运行中的应用保留；已经发起但尚未确认的请求会跨应用重启保留，直到收到成功结果。若出现幂等冲突或待确认请求损坏，保留应用数据并检查后端，不能清空后直接重建以免重复上报。

## API

| 方法和路径 | 成功结果 |
| --- | --- |
| `GET /health` | `200 {"data":{"status":"ok"}}` |
| `GET /api/events` | `200 text/event-stream`，连接发送 ready，保存后发送 issues-changed，客户端重新查询 |
| `POST /api/issues` | `201 {"data": issue}` |
| `GET /api/issues` | `200 {"data": issue[]}`，创建时间倒序、ID 稳定排序 |
| `GET /api/issues/{id}` | `200 {"data": issue}`，未知 ID 返回 404 |
| `PATCH /api/issues/{id}/content` | `200 {"data": issue}`；必传 title、description、priority，只修改内容及 updatedAt |
| `PATCH /api/issues/{id}/position` | `200 {"data": issue}`；如 `{"position":{"x":0,"y":1,"z":2}}`，只修改位置及 updatedAt |
| `PATCH /api/issues/{id}/status` | `200 {"data": issue}`，如 `{"status":"resolved"}`；status 仅 open / in_progress / resolved |

创建请求（零坐标有效）：

```json
{"title":"水管漏水","description":"入口附近","priority":"high","position":{"x":0,"y":0,"z":0}}
```

服务生成随机 ID、UTC createdAt / updatedAt 和 open 状态。标题去除首尾空白后必填；priority 仅 low / medium / high；position.x/y/z 必须提供且为有限数值。无效参数返回 `400 {"error":{"code":"invalid_argument","message":"可读错误"}}`；保存失败返回 500；未知接口返回 404。客户端不能设置 ID、状态或时间。单请求最大 64 KiB。

新建请求携带 `Idempotency-Key`（非空白，最多 200 字节）时，相同键与规范化内容重放返回 200 和首次创建的原始回执，不再创建问题；同键不同内容返回 409。规范化包含标题去除首尾空白、JSON 属性顺序及数值编码归一。问题状态后来改变不影响原始创建回执；当前值通过查询获取。键和结果持久化，并发请求也只创建一条。为兼容 #2，无键调用仍可创建，但没有去重保障；业务手机始终提供键。浏览器 CORS 允许 PATCH 和 Idempotency-Key。

## 验证与边界

内容修改示例：`{"title":"复查漏水","description":"已补充现场情况","priority":"low"}`。三个字段均必传且不接受 null，描述允许空字符串；标题和优先级沿用创建校验。不接受 status、position、ID 或时间。无效内容返回 400、未知 ID 返回 404、持久化失败返回 500；失败不改变原记录。内容和状态修改在同一锁下读取当前记录并原子保存各自字段，原始创建幂等回执保留。

位置修改必传 position.x/y/z，接受有限数值（含零），拒绝缺失/null、额外字段、非法 JSON、多对象和超过 64 KiB 的请求。位置、内容、状态在同一锁内读取最新记录并持久化各自字段，互不覆盖；同字段以最后成功保存为准。位置重试不会新建问题，但会再次更新 updatedAt；创建幂等回执仍保留创建时的位置。#5 的验证证据及待验收项见 [重新标记验收](docs/issue-5-acceptance.md)。

```powershell
cd backend
go test ./... -count=1
go vet ./...
cd ../web
npm run build
npm run lint
cd ../mobile/ar-probe
python verify_apk.py Builds/AR-Inspection.apk
```

API 测试使用真实 HTTP 服务及临时文件，覆盖创建、参数校验、CORS、幂等并发/规范化/冲突、保存后响应丢失、重启重放、状态切换、内容独立修改及保存失败不修改内存。浏览器和真机证据见 [#2 验收](docs/issue-2-acceptance.md)、[#3 验收](docs/issue-3-acceptance.md)、[#4 验收](docs/issue-4-acceptance.md)。构建成功和 APK 校验不等于真机功能通过。

SSE 仅在成功保存后广播，幂等创建回放和失败请求不广播；通知不带问题快照、不提供持久事件回放，重连后的全量查询补齐变化。每个订阅者最多积压一个失效通知，慢客户端不会阻塞写入；10 秒心跳及有界写超时处理失联客户端，退出时清理订阅。若使用代理，需关闭 SSE 缓冲并允许长连接。验证见 [#6 验收记录](docs/issue-6-acceptance.md)。

已实现上报、持久化、网页状态管理、手机历史内容编辑、重新标记及可选 SSE。待完成：手机与电脑各一段 3–5 分钟视频，及最终包同一问题 ID 的完整现场复验，见交付清单。当前交付不包含登录权限或公网部署。Depth 的接入和用户同机反馈不构成厘米级精度、白墙通用可靠性或长期跟踪保证；构建和真机验证分别记录。历史存在系统 LOW_MEMORY 退出，尚无长时间稳定性结论。

## 手机记录首页（Issue #11）

当前启动默认进入记录列表；点击“设置”配置并测试服务地址，点击记录查看/编辑详情。只有“新增问题”或详情中的“重新标记”进入相机；返回首页停止相机采集。新增流程为选点 → 快照预览（确认/重拍）→ 填写信息。旧待确认上报仍固定原服务和原请求重试。

快照目前仅预览，尚不随记录保存或上传；列表为无快照的已有记录预留展示。实体手机已验证无相机权限浏览记录及返回首页实际释放相机；权限拒绝操作、实际快照仍待验收，不能视为 #10 全部完成。28 项 Unity 导航检查、复现方式、APK 和验证边界见 [Issue #11 验收记录](docs/issue-11-acceptance.md)。

设置页提供“深度辅助：开/关”，默认关闭并记住选择。开启后下次采集请求深度，不支持时仍使用平面；发热或卡顿可关闭。
